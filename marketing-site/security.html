Security

Built to hold boundaries

A retrieval control layer only earns trust if it is trustworthy under the hood. These are the properties Find Anything is designed around. This is a posture summary, not a compliance certification.

Permission-aware retrieval

Scope is enforced on every request, server-side. Results never cross a permission the agent does not hold. There is no path by which retrieval widens its own access.

No document contents in telemetry

  • Traces capture decisions — scope resolution, ranking signals, conflict detection, coverage — not the private text of your files.
  • Receipts are designed to be shareable for audit without leaking source contents.

Excluded means excluded

Out-of-scope or unavailable sources are counted in coverage only when their existence is already known — recorded in inventory during a previously authorized sync. Their content is never fetched, extracted, indexed, quoted, or returned, and Find Anything cannot discover files the connected account can't enumerate. Uncertainty fails closed: if authorization is unclear or fails, content retrieval is blocked rather than attempted.

Auditable by construction

  • Receipts — a stored record of what each retrieval ran against: snapshots, permission context, configuration versions, and query parameters.
  • Replay — re-run a stored receipt; unchanged inputs replay deterministically.
  • Diffs — when inputs changed, a re-run produces a comparison of the two runs.

Honest capability claims

The Google Drive integration is built and tested, working in private beta; authenticated access is pending Google restricted-scope verification. Everything else is labeled Planned. Find Anything does not claim factual correctness, universal completeness, or access to sources you have not connected.

Responsible disclosure: report security concerns to security@findanything.dev. Do not include active credentials or private document contents in the initial report.
